# 文档质量校验清单

`<skill-dir>/tools/validate_doc.py` 使用两种明确 profile。质量校验不得用替换字符读取损坏的 UTF-8，也不得只按表格行数推断内容完整性。

## 文件清单完整性审计（铁律）

> **本审计适用于所有 profile、所有文档，是 Phase 2.6 和 Phase 6 的强制步骤。**

| 检查项 | 判定标准 |
|--------|---------|
| 文件集合一致 | 文档 `## 文件清单` 表格中的文件名集合与源码目录的直接普通文件集合**完全一致** |
| 漏文件 | 磁盘有但文档表格缺 = **失败**；必须补入 |
| 幽灵条目 | 文档表格有但磁盘无 = **失败**；必须删除 |
| 文件计数 | 概述中提到的文件数 = 表格行数 = 磁盘文件数 |
| 关键内容列 | 禁止写"Python 源码"、"文件资源"、"杂项文件"等泛化描述；必须包含具体符号/结构/配置 key 信息 |
| 空目录降级 | 源码目录为空但文档仍是 standard profile = **失败**；必须降级为 placeholder |

## 概述质量审计（铁律）

> **概述是文档的信息密度核心，直接决定 AI 和人类读者能否快速理解目录用途。**

| 检查项 | 判定标准 |
|--------|---------|
| 禁止模板套话 | 严禁"承载对应的实现或数据"、"构成该单元的主体内容"、"该单元与工程内相邻模块通过既有接口与文档契约交互"、"覆盖相关主题域的细分实现"等泛化句式 |
| 三要素真实 | 概述必须包含：(1) 目录在工程架构中的确切角色；(2) 核心文件/符号/数据的具体名称；(3) 上下游关系的具体模块名 |
| 信息密度 | 概述至少包含 2 个具体实体名称（类名、函数名、标准编号、配置 key 等） |
| 父目录概述 | 如果目录无直接文件、只有子目录，概述必须列出各子目录的文件计数与核心职责 |

## standard profile

适用于包含实质源码、标准材料或有效子模块的目录。

| 检查项 | 判定标准 |
|--------|---------|
| 标题与导航 | 有唯一 H1；文档开头有 `**导航**:` |
| marker | 新文档使用成对的 `folder-doc START/END` marker；历史单 START 作为审计项报告，不自动补写 |
| 概述 | 3–4 个实质句子，涵盖三要素（输入源、核心处理与时效、下游产物交付）；严禁使用泛化套话 |
| 文件清单 | 与 source directory 的直接文件集合逐项核对；报告 missing、stale、duplicate |
| 子目录 | 与直接子目录集合逐项核对，文档链接经共享 resolver 验证 |
| 关键符号 | Python 包按实际可见符号填写并通过 AST 真实性核验，说明列注明核心方法签名与类型注解 |
| 依赖关系 | 说明具体类名与能力契约，有实质上下游/同级关系和 `⬆/⬇/↔` 标记；本地文档链接有效 |
| 系统角色 | 说明系统分层架构、数据流向或核心处理模式（推荐附 ASCII 数据流），严禁泛化模板句 |
| 状态 | 使用 ✅ / 🔶 / ⬜ / 📦 / ❓ 中的一个明确标记 |
| 内容质量 | 无空段落、占位尖括号、无信息量套话或"工具文件/杂项/其他文件"等模糊描述 |

## placeholder profile

仅适用于空目录或只有无实质内容初始化文件的目录。

- 状态必须是 `⬜`，并明确"占位/待实现"。
- 概述允许 1–2 句。
- 系统角色可以引用父目录并描述预期用途，不要求 50 字。
- 不要求虚构 3 个关键符号、依赖关系或使用示例。
- 若 source directory 已出现实质文件，应失败并切换到 standard profile。

## 调用

```bash
# 默认根据文档状态和源码内容选择 profile
python "<skill-dir>/tools/validate_doc.py" <doc.md> --source-dir <source_dir>

# 同步闸门：任何失败返回非零
python "<skill-dir>/tools/validate_doc.py" <doc.md> --source-dir <source_dir> --strict

# 机器输出；stdout 只能包含 JSON
python "<skill-dir>/tools/validate_doc.py" <doc.md> --source-dir <source_dir> --strict --json
```

退出码约定：

- `0`：所选 profile 通过；
- `1`：文档质量检查失败；
- `2`：文件缺失、路径越界、编码损坏或参数/契约错误。

## 同步范围

- 本轮新增或对应源码目录发生变化的文档：阻断式 strict 校验。
- 未变化的历史文档：全局审计并报告，不因旧模板漂移而自动批量重写。
- **`--full` 模式**：全部文档均执行文件清单完整性审计，不论扫描器分类。
- 校验器只报告，不修改文档。
